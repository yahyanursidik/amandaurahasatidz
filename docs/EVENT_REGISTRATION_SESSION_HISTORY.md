# Operasional sesi, pendaftaran, dan riwayat asatidz

- **Edit sesi:** Admin membuka **Event → Jadwal & sesi → Edit** pada baris sesi. Judul, jenis, waktu WIB, ruang, syarat kehadiran, dan jendela check-in dapat diperbarui. Hari kegiatan tidak dapat dipindahkan melalui edit; buat sesi baru pada hari lain jika jadwal berpindah hari. API `PATCH /events/:eventId/sessions/:sessionId` memvalidasi kepemilikan sesi, hari, urutan waktu, dan mencatat audit perubahan.
- **Status event:** Dari katalog atau ikhtisar event, terbitkan draft, buka/tutup pendaftaran, atau buka kembali pendaftaran yang pernah ditutup. Pembukaan kembali ditolak bila batas penutupan waktu sudah lewat; ubah tenggat di pengaturan event terlebih dahulu. Aksi status melewati izin `events.publish` di server.
- **Landing event:** Program reguler menampilkan formulir langsung satu langkah (nama, email, WhatsApp, komunitas/lembaga, wilayah, dan rombongan opsional) **tanpa OTP pendaftaran**, kartu pilihan jalur, atau penyebutan jalur undangan. Batas rombongan mengikuti pengaturan event. Jika belum dibuka, kuota penuh, atau tenggat lewat, area tersebut menjelaskan alasannya secara khusus untuk reguler. URL `/events/:slug/register` tetap dapat dipakai. Jalur undangan memakai **halaman mandiri** dari tautan unik yang dikirim panitia; tautan pribadi tersebut adalah akses formulir tanpa langkah verifikasi tambahan. Informasi jalur itu hanya tersedia pada tautan undangan pribadi dan portal panitia, tidak di landing umum.
- **Riwayat asatidz:** **Admin → Data Asatidz → Profil → Riwayat event** menampilkan jumlah event pernah didaftar, disetujui, pernah hadir, ditolak, dan ditandai/menunggu. Baris event menunjukkan status persetujuan dan alasan terkini dari `participant_status_histories` bila panitia mencatatnya. Daftar peserta per event menunjukkan jumlah event per asatidz dan alasan untuk peserta ditolak, waitlist, atau menunggu; bila belum ada alasan ditampilkan dengan jelas sebagai belum dicatat.
